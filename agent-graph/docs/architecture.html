1. 要望と実現の対応

最初に伝えてもらった要望を左に、それを満たす仕組みを右に並べます。

要望どう実現したかどこにあるか
会話は Claude Code の fable が担当プロジェクト設定でモデルを fable に固定。fable は根エージェントとして計画と報告だけを行い、実装は書かない。.claude/settings.json, CLAUDE.md
コーディングは Codex の gpt-6-astraタスクの実行者を codex にすると、herdr の別 pane で codex exec -m gpt-6-astra が動く。単発用の /codex も同じ経路。run_graph.py, spawn_codex.py（agr / agc）
文書は文量に応じて軽いモデル150 行以下は doc-light（haiku）、それ以上は doc-heavy（sonnet）。判断基準は根エージェントの方針に書いてある。.claude/agents/doc-*.md
人向けは HTML、エージェント向けは md文書エージェントの規則として固定。人向けは docs/human/ に自己完結 HTML、エージェント向けは docs/agents/ に Markdown。.claude/agents/doc-*.md
起動ごとに project_name-No で採番起動時の hook がカウンタを進め、識別子を Claude に通知し、herdr の pane 名にも付ける。resume は番号を引き継ぐ。agent_hook.py
fable を根とした有向グラフで見たいタスク DAG・サブエージェント・Codex を 1 枚の有向グラフに描くダッシュボード。2 秒ごとに自動更新。graph_server.py, graph.html
親が子に何を投げたか分かるように辺のラベルにタスク題名か引き渡した成果物を表示。ノードを選ぶと、渡した指示の全文と受け入れ結果が出る。graph.html
ハーネスをしっかり危険操作の拒否、lint、受け入れコマンド、scope 検査、別モデルレビュー、worktree 隔離、予算。すべて決定的に判定する。harness.py, agent_hook.py
どのプロジェクトでも起動したらこの環境になるhooks・agents・skills・方針・スクリプトをユーザー層（~/.claude、~/.codex、~/.local/share/agent-graph）に置き、dotfiles から symlink。リポジトリには何も置かない。起動時の hook が <repo>/.agents/ を作り .git/info/exclude で隠す。install.sh, agent_hook.py
sandbox で動かしたい各ジョブを agent-runner コンテナで実行するモード。リポジトリと認証情報だけをホストと同じパスでマウントし、~/.ssh は持ち込まない。Codex は元々 --full-auto の sandbox 内。herdr_runner.sandbox_command, tool/runner/
tab ＝ プロジェクト、左 claude、右 手作業、を崩さないエージェントは仕事ごとに別 tab を作る（tab create --cwd <worktree>）。人の tab は割らない。done の tab は自動で閉じ、failed / 判断待ちは残す。herdr_runner.HerdrRunner, zsh/agent-graph.zsh
グラフエンジニアリングで自律開発タスクを状態付きノードとして tasks.yaml に書き、スケジューラが依存順に実行・検証・統合・PR まで回す。人は承認ゲートだけ。graph_model.py, run_graph.py

2. 2 層の置き場所

「毎回同じ環境になる」ための核心です。変わらないものはユーザー層に、リポジトリごとに変わるものはリポジトリ層に置きます。

設定の優先順位として、リポジトリ側の .claude/settings.json はユーザー層に上書きできますが、deny は緩められません。安全側に固定されます。

3. herdr の中の配置

今の使い方（tab ＝ プロジェクト、左 claude、右 手作業）はそのままです。エージェントは人の tab を割らず、仕事ごとに自分の tab を持ちます。

4. 1 つのタスクが通る道

タスクは次の順で進みます。どの段階で落ちても、戻り先が決まっています。

各段階で起きること

段階起きること失敗したら
1 計画fable が /plan の手順で tasks.yaml を書く。validate が accept 無し・循環・未定義 executor を弾く。書き直すまで実行できない
2 ready依存タスクがすべて done になったものだけが投入される。並列上限は --max-parallel。上流が失敗すると下流は待ち続ける。status に出る
3 隔離統合ブランチから agent/<S>/<id> を切り、worktree を作る。再試行は同じ worktree を使う。—
4 実行指示書（目的・scope・入力・成果物・受け入れ条件・前回の不合格理由）を渡して実行者を起こす。異常終了は不合格として 5 へ
5 検証accept コマンドを worktree で実行。分岐点からの変更ファイルが scope 内か検査。理由付きで再試行。上限で昇格か人へ
6 レビューCodex の差分は Claude reviewer が読む。accept を再実行し VERDICT を返す。指摘を添えて再試行
7 統合worktree を commit し、統合ブランチに --no-ff で merge。競合は人の判断待ち
8 PRhuman ゲート承認後、統合ブランチを push して gh pr create。レポートが本文になる。gh が無ければ failed（手動 PR）

5. ハーネス層

ハーネスは「振った先が壊れない」ための層です。プロンプトのお願いではなく、コードで判定します。

リスク仕組みいつ動くか実装
勝手に push・履歴破壊git push、reset --hard、clean -f、branch -D を拒否。統合は pr ノードだけ。Bash 実行前（PreToolUse）harness.DENY_BASH
破壊的コマンドルート・ホーム・親の再帰削除、sudo、curl | sh、chmod 777 を拒否。Bash 実行前同上
秘密情報の漏えい.env、.ssh、.aws/credentials の読み出しと、保護パスの編集を拒否。Bash / Edit / Write の前harness.PROTECTED_GLOBS
規約違反のコード.py を編集すると ruff が走る。落ちたら結果を返してその場で直させる。編集直後（PostToolUse）harness.lint_file
検証されていない「完了」accept コマンドが全部通るまで done にしない。単発委譲も [T1] タグがあれば hook が同じ検査をする。実行者の終了時harness.run_accept
頼んでいない場所の変更分岐点からの変更ファイルが scope の glob に収まるか検査。外れたら不合格。検証時harness.find_scope_violations
同じモデルの盲点Codex の差分は Claude reviewer が読む。実装者と検証者を分ける。検証合格後run_graph.run_review
並列作業の衝突タスクごとに worktree。合格分だけ統合ブランチへ。競合は人へ。実行前・統合時run_graph.ensure_worktree
静かに回り続ける再試行上限、タイムアウト、並列上限、時間予算、サブエージェントの深さと同時数の上限。常時tasks.yaml, settings.json
スクリプト経由でルールをすり抜けるジョブを agent-runner コンテナで実行。マウントした場所以外は存在しない。実行時（任意）herdr_runner.sandbox_command
何が起きたか分からない採番・委譲・検証結果・拒否をすべて events.jsonl に残す。ダッシュボードが読む。常時common.append_event

Codex は Claude Code の hooks の外で動きます。その代わり、--full-auto の書き込み範囲は worktree に限られ、出た差分は accept・scope・レビューの 3 つを通らないと統合されません。既にお使いの guard-dangerous-commands.sh などの hooks はそのまま併存します。両方が拒否しても害はありません。

6. グラフ層

ノードはエージェントではなくタスクです。エージェントはタスクを実行する労働力に格下げしました。こうすると中断・再開・差し戻しがファイル操作になります。

tasks.yaml のフィールド

フィールド意味必須
idノードの識別子。英数字と -、_。必須
title短い題名。root からの辺ラベルになる。必須
executorcodex / doc-light / doc-heavy / human / pr。必須
depends_on先に done になっていなければならないタスク。辺になる。任意
scope触ってよいファイルの glob。codex では必須。codex は必須
inputs / outputs受け取る成果物と作る成果物のパス。上流の outputs は自動で下流の入力になり、辺ラベルにも出る。任意
accept受け入れコマンド。全部 exit 0 で合格。codex / doc は必須
prompt実行者に渡す目的。scope・入力・受け入れ条件はスケジューラが足す。codex / doc は必須
review別モデルレビューの有無。codex は既定で true。任意
retry.max / retry.escalate_to再試行回数と、上限後の昇格先（別 executor か human）。任意（既定 1 / human）
timeout_sec1 試行の上限時間。任意（既定 1800）

タスクの状態遷移

再試行と昇格の規則

  • 不合格 1 回目は、同じ実行者に理由を添えて再試行する。
  • retry.max を超えたら escalate_to に昇格する。たとえば doc-light から doc-heavy へ。
  • 昇格先でも不合格なら人の判断待ちになる。
  • escalate_to: human なら、上限を超えた時点で人の判断待ちになる。

7. 可視化

ダッシュボードは tasks.yaml、実行状態、イベントログの 3 つを読み、1 枚の有向グラフに描きます。

見えるもの意味
根ノードClaude 起動 1 回 = project_name-No。fable。左上の選択で切り替える。
タスクノードtasks.yaml の 1 タスク。題名、実行者とモデル、試行回数、状態。枝の色は状態。
サブエージェント / Codex 単発Agent ツールや /codex で投げたもの。紫は Claude、青は Codex。
辺のラベル根から出る辺はタスク題名。タスク間の辺は引き渡した成果物のパス。サブエージェントへの辺は description。
状態の点未着手 作業中 判断待ち 完了 失敗
右パネル（ノード選択時）渡した指示の全文、受け入れコマンドごとの合否と出力、scope と違反、レビューの判定と本文、実行者の報告、branch / worktree / pane。
右パネル（未選択時）目標、状態別の件数、ハーネスが拒否した操作の一覧。

更新は 2 秒ごとです。実行に関与しないので、ダッシュボードを閉じても何も止まりません。

8. sandbox

ハーネスは「ルール」、sandbox は「壁」です。ルールは Bash ツール経由の操作を止めますが、スクリプトの中から呼ばれた操作は見えません。壁は OS が強制します。

実行者既定AGENT_GRAPH_SANDBOX=docker のとき
Codex--full-auto の sandbox。書き込みは worktree 内、ネットワークは既定で切れるさらに agent-runner コンテナの中
Claude headless（doc-light / doc-heavy / reviewer）hooks の拒否のみ。ホストのファイルは読めるagent-runner コンテナの中。マウントした場所しか見えない
根の claude（あなたと会話する fable）hooks の拒否のみ変わらない（人が見ている前提）

コンテナに持ち込むもの

  • リポジトリ、~/.local/share/agent-graph、~/.claude、~/.codex、~/.config/gh。すべてホストと同じ絶対パスにマウントする。worktree の .git 参照や認証情報の場所がそのまま使えるため
  • uv のキャッシュは名前付きボリューム。毎回 Polars を落とさない
  • ホストの uid:gid で動く。root 所有のファイルが残らない
  • ~/.ssh、~/.aws は持ち込まない。push は pr ノードがホスト側で行う

ネットワークの許可制（pypi / npm / GitHub / 各社 API だけ）はまだ入れていません。ファイルの隔離だけで事故の大半は防げるので、運用が落ち着いてから足すのを勧めます。

9. 自律ループと人の関与点

自律とは「人が見ていなくても正しく止まる」ことです。この構成で人が必要になるのは 3 か所だけです。

いつ誰が何をする
始めるときあなた要望か Issue を fable に渡す。fable が tasks.yaml を書き、あなたが目を通す。
判断待ちが出たときあなたgate pane か approve / retry / reject。理由はパネルと status に出る。
PR の前あなたhuman ゲートで統合結果を確認して承認。

それ以外の計画・実行・検証・レビュー・統合・PR 作成は自動です。スケジューラが落ちても状態はファイルに残り、同じコマンドで続きから再開します。

マージ前の人のゲートは、評価データが溜まって「外してよい」と分かるまで残すことを勧めます。events.jsonl に合否・試行回数・所要時間が残るので、どの振り分けが成功率が高いかを後から測れます。

10. 使い方

導入（一度だけ）

# dotfiles に置く
mv agent-graph ~/00_project/dotfiles/agent-graph
~/00_project/dotfiles/agent-graph/install.sh          # symlink を張る。何度実行しても同じ

# 手で行う 3 つ
diff ~/.claude/settings.json ~/00_project/dotfiles/agent-graph/claude/settings.merged.json   # 確認して置き換え
echo 'source ~/00_project/dotfiles/agent-graph/zsh/agent-graph.zsh' >> ~/.zshrc                 # pj が更新される
cat ~/00_project/dotfiles/agent-graph/codex/config.snippet.toml >> ~/.codex/config.toml      # gpt-6-astra 既定

# sandbox を使うなら
~/00_project/dotfiles/agent-graph/tool/runner/build.sh
export AGENT_GRAPH_SANDBOX=docker   # .zshrc に書けば常時

日々の流れ

cd ~/00_project/sumire
pj                       # tab を作り、左で claude が起動する。識別子 sumire-001 が通知される
agd                      # 右 pane で。ブラウザで http://127.0.0.1:8765/

# fable に要望を伝える → /plan → agr init → tasks.yaml → 起動
agr init     --session sumire-001
agr validate --session sumire-001
agr launch   --session sumire-001
agr status   --session sumire-001
agr approve G1 --session sumire-001     # retry / reject も同様。gate tab で a/r/x でも可

単発の小さな作業は /codex（agc spawn --accept ...）、短い文書は Agent ツールで doc-light に投げます。リポジトリ側に置くファイルはありません。

11. 制約と未確認事項

  • herdr の JSON 形（result.pane.pane_id、result.root_pane.pane_id）はあなたの起動スクリプトから確認できたので、定数の調整は不要になりました。残る未確認は herdr tab create --no-focus の有無です。無ければ作成後に元の tab へ戻す処理を足します
  • AGENT_GRAPH_PLACEMENT=split にすると以前の「根 pane を分割」方式に戻ります。その場合は pj が渡す HERDR_PANE_ID が分割元になります
  • docker sandbox モードは実機未検証です。イメージのビルドと、--user で動かしたときの Claude / Codex の設定書き込みを最初に確認してください
  • Claude サブエージェントへの委譲文は、開始時点では PreToolUse と SubagentStart を同種・先着順で対応付けます。同種の同時投入で一時的に入れ違うことがあり、完了時に transcript から補正されます
  • ruff は uvx 経由のため初回はネットワークが必要です。リポジトリの .gitignore に __pycache__/ と .venv/ が無いと、生成物が commit に混ざります（scope 検査は生成物を除外します）
  • Codex は codex login 済みで 0.153.0 以降、PR 作成は gh と origin が必要です。無ければ pr ノードは failed になり、レポートだけ残ります
  • git 管理外のディレクトリでも hooks と拒否は効きますが、worktree を使うスケジューラは動きません
  • 実機の herdr / Codex / Claude headless では未検証です。偽の herdr / codex / claude / gh で、何も置いていないリポジトリに .agents/ が生えるところから、再試行・レビュー差し戻し・承認ゲート・PR までを通しています
