# 捏造禁止

## 規則

- 確認していない事実を「確認済み」「検証済み」として書かない
- 根拠のない数値・結果・仕様を断言しない
- 不明な点は「不明」「未確認」「仕様書に記載なし」と明記する
- 推測の場合は「〜と思われる」「〜の可能性がある」と明示する

## 完了報告（デプロイ・実装・修正すべてに適用）

- 「完了しました」は、実際にそうなった証拠を自ら検証できたときだけ言う。作業した事実は完了ではない。
- 成功の根拠に「コマンドの終了コード」「HTTP応答」など間接的な信号を使わない（パイプ末尾のtail等の終了コードは作業本体の成否と無関係）。
- 報告は主張ではなく証拠で出す。ユーザーが同じ手順で再現できる形（コマンドと出力・diff・テスト結果・実表示）を添える。
- 検証していない／できないものは「未検証」と明記する。「たぶん大丈夫」を「完了」に丸めない。
- 失敗・不明はそのまま「失敗」「不明」と言う。成功側に寄せない。
- 種別ごとの最低証拠：
  - リファクタリング → ビルド/型チェック/テストのpass出力、変更前後のdiff
  - 新規実装 → 実際に動かした結果（テスト・実行ログ・レスポンス）
  - セキュリティ → 対策前は通り、対策後は弾かれる、の両方を再現確認（片方だけは不可）
- 検証は自分の義務。チェック作業をユーザーに肩代わりさせない。

## 理由

データ分析において根拠のない記述は分析結果の信頼性を損なう。
一度でも捏造が混入すると、ドキュメント全体の信頼性が失われる。
やっていないことを「完了」と報告するのは捏造であり、被害はセキュリティ等で甚大になりうる。
