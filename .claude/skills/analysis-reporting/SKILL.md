# 分析レポートの書き方

## 基本姿勢: 実行結果に基づいて書く

コードを書いたら実行し、出力（数値・表・グラフ）を読んでからMarkdownを書く。  
実行前に書いたMarkdownは「ロジックの説明」に過ぎない。「わかったこと」は必ず実行後に追記する。

## Markdownセルの構成

各セクションに以下を揃える:

```
**問い** — このセクションで何を明らかにするか
**判定ロジック** — どのカラム・どの値で何を判断したか（箇条書き）
**わかったこと** — 実行結果に基づく発見（箇条書き・具体的数値入り）
```

## 箇条書きの書き方

- 1行1事実。解釈と事実を混ぜない
- 数値は具体的に入れる（「増加した」ではなく「2023年 11% → 2026年 28%（+17pt）」）
- 比較軸を明示する（最大/最小・上振れ幅・倍率・絶対数を使い分ける）
- データの限界・注意点（代替手段の理由・記録漏れの可能性）も必ず記載する

## 判定ロジックの書き方

- どのテーブル・カラムを使うか
- どの値・条件で判定するか
- 除外条件がある場合はその理由も書く

例:
```
- 来場記録は `estimated_visitor.csv` を `final_fid × game_time の日付` でJOIN
  - `is_game == "true"` の行のみ使用（試合開催日の来場に限定）
- 来場率 = JOINで一致した件数 ÷ その取得方法の最終保有者数
- 2026年は来場データが7件のみのため2025年で代替
```

## Notebookがレポートになるレベルとは

- Markdownを読むだけで「何を調べ・何がわかったか」が理解できる
- コードセルの出力とMarkdownの「わかったこと」が1対1で対応している
- 判定ロジックが明示されており、数値の根拠が追跡できる
- まとめセルに全体の発見・示唆が集約されている
- 造語・曖昧な表現を使わず、データの用語をそのまま使う

## まとめセルの書き方

表形式で主要数値を列挙した後、全体の示唆を2〜3文で締める。

例:
```markdown
| 項目 | 数値 |
|---|---|
| 二次流通率（2026年公式戦15試合） | 分配28% + リセール25% = 53% |
| ...

**全体を通じて**
2026年の分配義務化によって...
```
